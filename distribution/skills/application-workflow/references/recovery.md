# 恢复

除非当前状态证明某项已报告完成的操作并未生效, 否则把它的结果视为持久状态. 不得虚构跨操作回滚.

## Association files

Application 关联使用每个仓库的 Git 索引作为文件恢复基线. 写入失败时, 检查每项已报告完成的操作和恢复结果. 恢复失败表示具名工作树路径可能与其 Git 索引不同. 在用户审查实际字节前, 不得暂存或继续发布.

## Branch switching and synchronization

子模块分支切换会预检所有 Module, 并在切换失败后按相反顺序尝试恢复. 检查每个 Module 最终报告的分支和提交.

同步操作保留在后续 Module 失败前已经完成的 Module 快进, 不得向后移动该分支. 修正后续阻断项后, 从当前状态重试.

失败的 Application issue 事务会报告已完成的文件操作和每项回滚结果. 重试前, 把未恢复的路径与 Application Git 索引基线进行比较.

## Git publication

成功的提交或推送保持有效. 如果后续操作失败, 检查本地 `HEAD`, 上游分支, Application 子模块 gitlink 和 Module 分发分支. 从已确认的状态继续向前, 不得只因响应结果不确定就假设推送失败.

## JIRA convergence

JIRA 接受和完成操作会在更改状态前创建准确的评论. 如果评论创建成功但状态转换失败, 保留该评论. 修正阻断项后重试同一命令, 命令会找到现有的准确评论, 并且只执行缺失的状态转换.

当 HTTP 结果不确定时, 在再次写入前重新读取 Git 和 JIRA. 不得把删除有效评论或反转有效状态作为自动恢复方法. 任何新的提交, 推送, JIRA 写入或破坏性修复仍需要普通授权.
