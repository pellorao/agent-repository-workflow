# 规则和设计更改的用户批准

## Scope and authority

修改 Agent 指令或保存持久设计或治理的文档前, 识别精确的目标路径批次, 并为用户审查建立隔离的 Git 索引状态.

用户的直接请求授权按照本文档准备拟议的工作树修改, 但不构成对这些修改的批准. 无论由谁请求修改, 都应用相同边界.

根据文档责任对它进行分类, 不得使用封闭的路径列表. Agent 指令, Skill Package, 长期规范, ADR, 上下文文档, 以及保存持久设计的跟踪器内部规范或 PRD 受保护. 不负责持久设计或治理的普通 issue 完成证据和其他工作记录, 不会仅因文件类型而受保护.

把长期规范编写为当前持久设计. 陈述最终行为, 责任, 公开或架构边界, 以及维持这些选择所需的理由.

把实施步骤, 单个 issue 的迁移工作和已经被取代的实施历史放入适用的 issue, 验证证据或其他工作记录. 替换原有行为时, 陈述最终合同及其长期理由, 不得在长期规范中叙述旧机制.

把 ADR 写为当前有效的决定, 维持该选择所需的理由, 以及仍有意义的被否决方案. 只有紧邻当前选择的前一次决定有助于解释当前取舍时, 才简要标明这一段历史; 不累积多轮旧决定, 日期日志或实施细节. 完全被取代的 ADR 保留原编号和路径, 只说明取代关系并链接现行决定. 更早的正文由 Git 历史保存.

## Establish the comparison

所有写入先遵循 [共同写入规则](agent-writes.md). Main Agent 在自己修改或分派文档写入前, 为本节的用户比较准备准确基线. 编辑现有目标前, 检查其已暂存和未暂存状态. 干净的目标已经具有隔离的 Git 索引比较.

如果目标包含先前变更, 只有在每个受影响字节都已经证明属于当前 issue, 且用户已经接受时, 才把它暂存为比较状态. 如果任何现有变更属于其他责任方, 责任归属不确定, 或包含当前 issue 中尚未接受的内容, 停止受影响的修改并请求指示.

只使用精确的 pathspec. 不得使用 `git add -A`, 不受限的 pathspec 或其他覆盖整个仓库的暂存操作来建立该比较.

只在精确批准的范围内创建新目标. 请求审查前, 使用 `git add -N -- <path>` 标记该精确新路径, 使其完整内容出现在普通未暂存比较中, 而不进入已暂存字节.

## Human review

准备修改后, Main Agent 按[面向用户说明](user-communication.md)解释并请求具体差异批准, 提供精确目标路径, 变更摘要及审查相对于 Git 索引的完整未暂存比较命令 `git diff -- <paths>`.

除非用户请求差异或无法检查本地比较, 否则无需把完整差异复制到对话中. 用户要求的任何修订都保持未暂存, 并替换用户必须审查的比较.

可审查的工作树差异建立后, 用户必须在后续响应中明确批准. 只有列出精确批次, 且本地比较包含每个所列路径的完整拟议变更时, 一次批准才可以覆盖多个文件. 只有在已审查的 Git 索引状态和工作树字节保持不变时, 批准才在当前对话中有效. 不得通过交接, issue 评论, Agent 摘要或其他对话继承批准.

## After the decision

批准后, Main Agent 只使用 `git add -- <paths>` 暂存精确批准的路径. 这些已暂存字节成为同一 issue 后续审查轮次中已接受的比较状态. 暂存批准不授权提交.

如果用户拒绝完整方案并明确请求完全回滚, 只把精确批次中的现有目标路径恢复为其 Git 索引字节. 对该批次创建的新目标, 先删除其 intent-to-add 状态, 然后只删除相应精确文件. 不得丢弃或取消暂存被拒绝批次之外的路径.

如果真实目标无法安全使用仓库的 Git 索引, 就在当前 issue 的 ARW Engine 管理临时工作区下建立隔离的 Git 仓库, 并遵循相同的准备和用户审查流程. 把精确目标复制到其中, 将它们暂存为比较状态, 并使用 `git -C <temporary-root> diff -- <paths>` 审查. 批准后, 把已批准变更应用到真实目标, 并保持真实仓库的 Git 索引不变.
