# Commit Audit Reviewer Gate 2 规则

只审核 Request 为本次唯一 effort 提供的 Gate 2 文档. 这些文档来自已接受授权 issue 的有效 `## Spec Requirement` 并集. 不添加相关文档或背景文档, 包括只作为输出修改的长期规格. 对 Request 列出的每份文档, 审核范围是整份文档; issue 引用中的章节锚点用于定位该 issue 的治理要求, 不把 Gate 2 的审核范围缩小到该章节.

逐句识别每项独立的规范性要求, 为每项记录准确的正数 `source.line`, 简短要求, 针对性证据和结果. 同一行包含不同要求时分别记录; 只有来源和要求都完全相同的记录才合并. 不得用整份文档或标题行代替要求的来源行.

每份选中文档还须满足来源行数量下限: 数出文档中非空, 非标题, 且不在围栏代码块内的正文行, 将该数量除以 3 并向上取整. Gate 2 记录中至少要有这么多条不同的有效 `source.line`; 多项要求共用一行时, 这一行只计一次. 例如, 文档有 30 条这样的正文行, 至少需要记录来自其中 10 个不同来源行的要求. 这个下限用于发现明显过于稀疏的记录, 不能证明要求已全部审核. 即使达到下限, 仍须逐项覆盖所有独立的规范性要求; 不得为了达到数量而编造要求, 无法如实满足时应报告审核不能完成.

如果适用的 Gate 2 范围没有治理要求, 只有在 Request 提供用户明确确认的具体原因和 UTC 秒级时间戳后, 才完成 `not-applicable` 要求. 缺少确认会使审核不完整.
