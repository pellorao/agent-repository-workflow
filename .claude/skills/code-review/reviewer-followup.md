# 后续审核与问题处理

[结论复用](result-reuse.md)要求新判断时, 只对实际受影响的轴准备完整当前输入, 按[公共复审规则](../../../docs/agents/reviewer.md#review-changes-and-prior-coverage)检查相邻版本差异及关联影响, 并取得完整当前结果. 按技能主文件定义的身份复用可靠原线程.

Main Agent 需要中途结果时, 可以在审查期间读取各绑定报告文件. 对需要处理的问题独立核对后, 再请求必要的用户决定. 在每个适用轴交付其完整当前结果前, 固定的比较对象和完整输入副本保持不变. 这些审查进行时, 已授权修复可以在源工作树中推进; 每条结论只适用于其固定的受审版本, 改变后的最终候选按结论复用规则取得替代审查. 拟议修复更改 Agent 指令或持久设计或治理文档时, Main Agent 必须在编辑前遵循仓库的用户批准规则. 提供所引用的证据, 推理, 保持候选不变的影响, 拟议修改, 以及受影响验证和审查的成本. 用户接受问题的决定不等于批准具体差异. 修订或撤回原位更新同一报告文件; 根据完成后的文件内容判断最终结果. 未完成文件不能替代每个轴所需的完整当前结果.

只有 issue ID 集合变化, 原线程不可用或不可恢复, 或用户明确要求时, 才创建新的替代线程. 候选字节, 摘要值, 文件哈希, 治理或产品语义, 问题和结论发生变化, 本身不会要求新线程. 不设固定复用次数或时限. 允许替代时, 按 [启动与控制 Reviewer 的共同步骤](../../../docs/agents/reviewer.md#machine-operations)启动不继承父会话的独立线程; 不发送旧问题, 作者讨论或修复历史. 每轮新审查都准备新的空报告文件. 原 Reviewer 线程仍可靠时, 使用相同角色, issue 身份和 `stateDirectory` 调用 `followup_task`, 交付完整的新审查任务及新的报告绑定. 原线程已安全卸载时, 管理进程先在内部恢复准确原线程, 再交付任务. 工具进程会话丢失后重新连接, 使用 `list_agents` 或 `wait_agent` 观察既有审查; 不因控制连接结束而创建替代线程. 只有允许替代时才使用 `spawn_agent`, 并在该次调用中包含完整首次任务.

再次交付技能主文件要求的全部当前输入, 包括 Spec 轴完整治理要求, 以及公共规则允许的自身前轮原始报告和绑定输入. 先前问题, 修复位置和变化说明只提示需要核对之处, 不替代当前证据. 默认差异复审, 仍请求完整当前报告而非变化条目; 全盘例外由 Reviewer 按公共规则说明具体理由.
