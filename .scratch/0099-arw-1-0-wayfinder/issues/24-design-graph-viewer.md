# 设计给人看的 graph 查看界面

Type: prototype
Blocked by: issue:0099:19, issue:0099:22

##### Question

用户 11-13 在 D26 中要求: 1.0 要有给人看的 graph 查看界面, "以人类能读懂的方式展现, 而不是一个屏幕上摆上几百个节点和几千根连线", 从最上层开始看, 需要时才看下面的细节. [定义规则到 graph 的转换与 Engine 按 graph 执行](22-define-rule-to-graph-conversion.md) 已把 graph 分层为有名字的子流程 (头部有说明, 输入, 返回值与必经边, 用 `call` 调用), 并为每个子流程生成路径摘要. 查看界面怎样从顶层子流程开始按需展开: 一层显示什么 (子流程说明, 节点与边, 返回值, 路径摘要), 怎样进入被调子流程和返回, 怎样按节点全名, 关键词或参数定位, 怎样显示一个实例当前所在的节点和走过的路径? 它放在哪里: [确定 Engine 对话入口的形态](19-decide-conversation-entry-form.md) 的网页入口中的一页, 还是 graph 命令行工具生成的静态页面? 首版只读还是也能改 graph? 用一个以试转换的 commit 流程 (4 层, 74 个节点) 为数据的可丢弃原型检验, 单屏节点数不超过一个子流程 (试转换中最多 11 个).
