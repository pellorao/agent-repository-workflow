Type: task

##### Question

用一批取自 ARW 公开仓库的带标签分流, 预检和输出检查案例 (约 100 到 200 条, 标签为高智能 Agent 或人工给出的正确判断), 在本机实测选定本地候选的判断准确率, 置信度分布, 单次延迟与显存占用; 用同一批案例对托管 Jev 测速度与准确率作为基准, 另可加入其他托管替代方案; 得出本地运行是否可行的事实. 托管服务只接收 ARW 公开仓库中的案例, 私有内容只给本地候选; 托管 API 凭据由用户放在仓库外的本地私有文件, 只由脚本引用, 不进入 Git, 日志, 报告和提示词, 这一步作为用户动手步骤先说明再做. 本地运行需要 GPU, 由 Main Agent 按本机资源规则另行排期, 下载和写盘量先报批.

- 防火墙: 第一次绑定非 `127.0.0.1` 地址时, Windows 防火墙为 `llama-server.exe` 弹出提示, 无人应答, 系统自动生成 2 条 Public 入站 Block 规则 (TCP 与 UDP), 压过已有的端口放行规则, WSL 访问超时; 绑 `127.0.0.1` 不触发提示. 删除这两条规则和新增放行规则都要管理员权限; 用户以管理员删除后加了一条只放行该程序, 该 TCP 端口和本地子网的规则, 之后不再出现提示.
- WSL 访问: WSL 中的程序按 WSL 默认网关地址 (即 Windows 侧虚拟网卡地址) 访问, `/health` 与 `/v1/systemone` 都通. 07 的 Comments 中 "Windows 防火墙对非回环监听的提示" 由此得到一个实例; "WSL NAT 网络模式下局域网设备能否连入" 仍未核实, 本次只验证了 WSL 到 Windows.
