# 确定 Engine 对话入口的形态

Type: grilling
Status: resolved
Blocked by: issue:0099:07

##### Question

Engine 对入口提供与形态无关的会话事件流和命令接口 (见 [定义 Engine 驱动流程的运行合同](07-define-engine-runtime-contract.md)), 首版用户实际通过什么与 Engine 对话: Engine 自绘的终端界面, Engine 在本机回环地址上提供的网页, 还是复用 Codex 与 Claude Code 自己的交互界面并经 hook 等扩展点接入? 是否另外把 Engine 暴露为 ACP agent, 让支持 ACP 的编辑器和客户端作为前端? 远程与手机使用, Windows 原生 PowerShell 是否为首版硬要求? 事实见 [Engine 自有对话入口的形态比较](../research/engine-entry/report.md).

## Answer

用户 11-11 在三个候选 (Engine 自绘终端界面, Engine 提供的本地网页, 复用 Codex 与 Claude Code 自己的交互界面) 中选了本地网页, 并补充 (原话): "本地网页, 但会也监听外部请求, 这样用户在其他地方也能访问到. 目前暂时不需要用户名密码, 但需要和状态页一样的 "用授权码添加设备" 逻辑." 其中 "状态页" 指用户自用的一个本机网页服务, 它对局域网开放 HTTPS 访问, 新设备第一次连接时输入在本机生成的一次性授权码, 换得该设备的凭据, 之后每次请求都核对设备凭据, 设备可以逐个撤销. 以下是 Main Agent 对答复的理解, 11-12 记录.

- 首版入口: Engine 自带的网页, 作为 [定义 Engine 驱动流程的运行合同](07-define-engine-runtime-contract.md) 中事件流加命令接口的客户端. 不只监听本机回环地址, 局域网和远程设备也能连接, 所以远程与手机使用是首版要求, 不是以后的扩展.
- 访问控制是入口的必备部分: 首版不设账号密码; 非回环访问一律走 TLS; 未配对的设备只能看到配对页; 设备第一次连接时用一次性授权码配对 (授权码只能从已信任的一侧生成, 例如本机命令或本机回环地址上的页面, 短时有效, 限制尝试次数), 换得设备凭据, 之后每个请求核对设备凭据; 已配对设备可以列出和撤销; 凭据与授权码只存哈希, 放在用户私有运行状态中. 批准请求和待答事项只对已配对设备展示和接受应答. 证书来源 (自签 CA 或用户提供的证书), 默认端口, 凭据有效期, 配对尝试上限等参数由规范正文定.
- 不采用复用 harness 交互界面的形态 (它让用户的话先进入 harness, 与 Engine 先接收用户的话相左). 终端界面以后如需要, 可以作为同一接口的另一个客户端再加, 不进首版. 用户没有要求把 Engine 暴露为 ACP agent, 首版不做.
- 影响: Engine 对外监听网络连接, 是 Engine 宿主进程的攻击面; 宿主进程的选择 (是否由现有用户级后台管理进程扩展) 要把这一点计入, 见 07. 主动通知 (浏览器通知或推送) 与 Windows 原生运行的验证要求在规范正文中写明.
