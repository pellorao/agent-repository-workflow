# 定义 Engine 调用 Jev 类模型的接入方式

Type: grilling
Status: resolved
Blocked by: issue:0099:05

##### Question

Jev 类模型只回答固定选项问题, 不是 Agent: Engine 应直接调用 `/v1/systemone` 兼容接口 (托管 Jev 与多数开源候选都提供), 还是把它作为后台 Agent 提供方接入现有用户级管理进程 (同 Strata 的方式)? 托管与本地候选怎样切换, 凭据, 超时, 不可用时的回退 (直接交高智能 Agent) 和调用记录放在哪里?

## Answer

事实见 [Jev 类模型接入方式的事实核对](../research/judge-model-integration/report.md) (11-09). 结论由 worker 分析, 交 Main Agent 综合; 本地判断服务由谁启动和管理见 [确定本地判断模型服务的运行责任](18-decide-local-judge-server-ownership.md). 11-11 按该 issue 记录的用户答复 (判断模型是必需组件, 不退化为交给高智能 Agent) 改写了本答案的超时与失败部分, 原写法 "任何失败都按未分流交高智能 Agent" 作废. 11-14 按用户 D24 答复 (判断模型可选, 配了只做提示) 再次改写超时与失败部分, 11-11 的 "必需组件, 失败时停在可恢复状态" 作废, 见 Comments.

调用路径: Engine 在自己的进程内直接调用 `/v1/systemone` 兼容接口, 不把 Jev 类模型接成后台 Agent 提供方. 理由: 现有提供方的产物是供 Codex App Server 会话使用的推理端点, 以会话实例计容量, 以 lease 独占显卡; Jev 类调用是无状态的单次请求, 没有会话, 回合, 批准或压缩, 厂商声称 70 到 500 ms, 经管理进程中转只会增加一跳和一种失败方式. 托管 Jev, Laya 与 NeoHorse 用同一路径和大体相同的请求形状, 所以一个客户端可以覆盖托管与本地候选.

接口子集: ARW 只使用 `model`, `state`, `questions` (题型 `choice` 与 `noul`; `score` 与 `box` 没有对应的分流, 预检或输出检查用途, 不使用) 和响应的 `model`, `answers` (所选项与 `probabilities`), `usage`. 同一 `state` 的独立问题合在一次调用里, 每题只问一个窄问题, 由 Engine 代码合并结果 (厂商建议). 判断依据是所选项的概率, 不是 `confidence` (见 [核对 Jev 类判别模型的能力与候选](02-research-jev-class-models.md)). 每个候选在启用前要通过一组固定题目的兼容核对 (响应含上述字段, 概率之和为 1, 返回实际模型名), NeoHorse 等未声明兼容的候选不预设兼容.

配置与切换: 判断模型写在 ARW 用户级配置 (与 `backgroundAgent.providers` 同一文件, 但另设一节), 每项给出端点, 请求用的模型名, 凭据引用和超时; 另按提示类别 (预检, 输出检查, 修复核对, 对 Agent 输出字段的核对) 指定使用哪一项. 这一节可以为空: 判断模型可选 (D24), 未配置时 Engine 不提题, 首版按 18 的使用条件实际不配. 托管与本地之间切换只改配置, 不改流程代码. 每次调用记下响应中的实际模型版本, 别名 (如 `jev-latest`) 漂移时由记录发现, 评测与启用按实际版本计.

凭据: 托管密钥放在仓库外, 用户自己的私有文件中, 配置只写文件路径; Engine 每次调用时读取, 不写入日志, 调用记录, 报告, 提示词或错误信息 (现有 Strata 驱动对 lease 密钥的脱敏做法可以沿用). 本地服务默认只接受本机连接; Laya 默认绑定 `0.0.0.0`, 启用时须改为 `127.0.0.1` 或开启 Bearer 认证, 这一点写进安装与配置说明.

超时与失败 (11-14 按 D24 改写): 每次调用有一个总时限 (含重试; 默认值在评测中按实测延迟确定). 判断模型配了只做提示, 失败都不是运行故障: 该题不提示, 流程照常, 不改由高智能 Agent 代答, 不停流程, 也不为此打断用户; 失败类别与原因记入调用记录 (07 的可观察内容).

- 暂时过载: 429 与 529 在时限内按厂商建议短暂退避后重试一次, 仍失败则该题不提示.
- 服务不可用 (连接失败, 超时, 其他 5xx) 与配置或兼容错误 (401, 422, 响应字段不符): 不重试, 该题不提示. 服务由用户或其部署方维护, 首版 Engine 不负责开启或重启判断模型 (20).
- 单题超出输入上限 (400 含 `max_tokens_exceeded`, 413): 不截断后再问, 因为截断会改变判断依据; 该题不提示, 并记入调用记录, 供修订题目模板.

调用记录: 写在 Engine 的流程运行状态中 (ARW 安装目录下的用户私有运行状态, 不写进仓库 `.scratch`), 每次调用一条: 时间, 流程与步骤, 题目 ID 与题目模板版本, 配置项与实际模型版本, 所选项与各选项概率, 延迟, `usage`, 结果 (已判断, 或失败类别及原因), 以及核实它的会话是否判该提示无效 (供 11 的线上无效比例). 默认不保存 `state` 原文, 只保存其长度, 哈希和来源 (仓库提交与文件路径; 含未提交内容时只记路径, 不保证能重建); 是否允许保存原文由 [定义 Jev 类模型的评测与启用条件](11-define-evaluation-and-graduation.md) 的托管内容边界决定.
