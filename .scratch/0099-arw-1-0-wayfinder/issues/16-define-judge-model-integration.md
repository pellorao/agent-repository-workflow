# 定义 Engine 调用 Jev 类模型的接入方式

Type: grilling
Status: resolved
Blocked by: issue:0099:05

##### Question

Jev 类模型只回答固定选项问题, 不是 Agent: Engine 应直接调用 `/v1/systemone` 兼容接口 (托管 Jev 与多数开源候选都提供), 还是把它作为后台 Agent 提供方接入现有用户级管理进程 (同 Strata 的方式)? 托管与本地候选怎样切换, 凭据, 超时, 不可用时的回退 (直接交高智能 Agent) 和调用记录放在哪里?

## Answer

事实见 [Jev 类模型接入方式的事实核对](../research/judge-model-integration/report.md) (11-09). 结论由 worker 分析, 交 Main Agent 综合; 本地判断服务由谁启动和管理见 [确定本地判断模型服务的运行责任](18-decide-local-judge-server-ownership.md). 11-11 按该 issue 记录的用户答复 (判断模型是必需组件, 不退化为交给高智能 Agent) 改写了本答案的超时与失败部分, 原写法 "任何失败都按未分流交高智能 Agent" 作废.

调用路径: Engine 在自己的进程内直接调用 `/v1/systemone` 兼容接口, 不把 Jev 类模型接成后台 Agent 提供方. 理由: 现有提供方的产物是供 Codex App Server 会话使用的推理端点, 以会话实例计容量, 以 lease 独占显卡; Jev 类调用是无状态的单次请求, 没有会话, 回合, 批准或压缩, 厂商声称 70 到 500 ms, 经管理进程中转只会增加一跳和一种失败方式. 托管 Jev, Laya 与 NeoHorse 用同一路径和大体相同的请求形状, 所以一个客户端可以覆盖托管与本地候选.

接口子集: ARW 只使用 `model`, `state`, `questions` (题型 `choice` 与 `noul`; `score` 与 `box` 没有对应的分流, 预检或输出检查用途, 不使用) 和响应的 `model`, `answers` (所选项与 `probabilities`), `usage`. 同一 `state` 的独立问题合在一次调用里, 每题只问一个窄问题, 由 Engine 代码合并结果 (厂商建议). 判断依据是所选项的概率, 不是 `confidence` (见 [核对 Jev 类判别模型的能力与候选](02-research-jev-class-models.md)). 每个候选在启用前要通过一组固定题目的兼容核对 (响应含上述字段, 概率之和为 1, 返回实际模型名), NeoHorse 等未声明兼容的候选不预设兼容.

配置与切换: 判断模型写在 ARW 用户级配置 (与 `backgroundAgent.providers` 同一文件, 但另设一节), 每项给出端点, 请求用的模型名, 凭据引用和超时; 另按判断类别 (分流, 预检, 输出检查) 指定使用哪一项. 托管与本地之间切换只改配置, 不改流程代码. 每次调用记下响应中的实际模型版本, 别名 (如 `jev-latest`) 漂移时由记录发现, 评测与转正按实际版本计.

凭据: 托管密钥放在仓库外, 用户自己的私有文件中, 配置只写文件路径; Engine 每次调用时读取, 不写入日志, 调用记录, 报告, 提示词或错误信息 (现有 Strata 驱动对 lease 密钥的脱敏做法可以沿用). 本地服务默认只接受本机连接; Laya 默认绑定 `0.0.0.0`, 启用时须改为 `127.0.0.1` 或开启 Bearer 认证, 这一点写进安装与配置说明.

超时与失败 (11-11 改写): 每次调用有一个总时限 (含重试; 默认值在评测中按实测延迟确定). 判断模型是必需组件, 失败按三类处理, 都不改由高智能 Agent 代答:

- 暂时过载: 429 与 529 在时限内按厂商建议短暂退避后重试一次.
- 服务不可用 (连接失败, 超时, 其他 5xx): 本机部署时 Engine 重新执行开启脚本, 等就绪检查通过后重试一次; 机构内部或公开部署没有本机进程, 短暂退避后重试一次. 仍失败时流程停在可恢复状态 (该步没有产生副作用, 流程状态已保存), 告诉用户原因和处理办法; 用户处理后, 或 Engine 重新核对通过后, 从该步继续.
- 配置或兼容错误 (401, 422, 响应字段不符): 不重试, 同样停在可恢复状态并报告, 因为重试不会改变结果.

单题超出输入上限 (400 含 `max_tokens_exceeded`, 413) 不是服务不可用: 判断模型可用, 只是这道题无法作答. 不截断后再问, 因为截断会改变判断依据; 该题按 "未达概率阈值" 处理, 走 [定义分流判断的复核与回退合同](08-define-routing-review-and-rollback.md) 定义的低置信度路径, 并记入调用记录, 供修订题目模板. 判断可用时什么条件下可以直接触发动作, 也属于该 issue.

调用记录: 写在 Engine 的流程运行状态中 (ARW 安装目录下的用户私有运行状态, 不写进仓库 `.scratch`), 每次调用一条: 时间, 流程与步骤, 题目 ID 与题目模板版本, 配置项与实际模型版本, 所选项与各选项概率, 延迟, `usage`, 结果 (已判断, 或失败类别及原因), 以及事后高智能 Agent 对同一问题的结论 (供分歧统计). 默认不保存 `state` 原文, 只保存其长度, 哈希和来源 (仓库提交与文件路径; 含未提交内容时, Engine 在调用时把这些文件写成 Git 对象, 来源记对象 ID, 见 [定义并行流程的读取与写入隔离](10-define-parallel-flow-isolation.md)), 需要复查时按来源重建; 是否允许保存原文由 [定义 Jev 类模型的评测与转正条件](11-define-evaluation-and-graduation.md) 的托管内容边界决定.
