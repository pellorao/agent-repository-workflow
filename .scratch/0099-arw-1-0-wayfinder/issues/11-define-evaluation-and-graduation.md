# 定义 Jev 类模型的评测与转正条件

Type: grilling
Status: resolved
Blocked by: issue:0099:02, issue:0099:05, issue:0099:12

##### Question

以用户发出消息到 Agent 结束回复的时长, 结果质量和用户满意度为指标, 怎样建立当前 ARW 的基线, 评测托管 Jev 与本地开源候选, 并按任务类别决定何时从全量高智能复核改为抽样复核? 漂移, 回退和停止使用某类判断的条件是什么? 托管评测可以发送哪些仓库内容?

## Answer

结论由 worker 分析, 交 Main Agent 综合. 下文的数值是首版默认, 用 [本地 Jev 类候选的可行性小实验](15-task-local-candidate-feasibility.md) 的结果校准后写入规范; 它们是可调参数, 不是新的用户决定.

指标与基线:

- 时长: 一个流程从用户发出消息到 Agent 结束回复的墙钟, 只计 Agent 工作时间, 外加审核轮数. 现行 ARW 的基线来自 [测量当前 ARW 流程的耗时分布](12-research-flow-time-baseline.md): 每个实施 issue 中位数约 15 到 25 分钟, 提交审核通常 2 到 5 轮. 1.0 的 Engine 自己记录每步起止时间, 不再从会话记录推算; 同一类流程以 1.0 关闭判断模型 (全部交高智能 Agent) 时的时长作为对照, 因为 Engine 本身也会改变时长, 只与现行 ARW 比较会把两种变化混在一起.
- 结果质量: 沿用现行 ARW 的质量守护, 即 Reviewer benchmark 的盲评分与真实缺陷检出不下降; 对每类判断另计 "有害分歧", 即判断模型的结论被高智能复核推翻且已据此执行了动作.
- 用户满意度: ARW 不能直接测量, 用 Engine 记录中可数的替代量: 用户推翻或要求重做已交付结果的次数, 以及因判断错误而需要用户介入的回退次数. 只靠替代量是已知局限, 规范中写明.

离线评测 (每类判断, 每个候选, 每个模型版本各一次): 用带标签案例集 (标签来自高智能 Agent, 人工抽查) 分出校准集与测试集. 必测: 准确率, 所选项概率的校准 (ECE 与分桶准确率), 高概率错误率, 调换选项顺序后的翻转率, 单次与批量延迟, 成本. 在校准集上为每类判断选一个概率阈值, 使阈值以上的测试集精度不低于 0.95; 阈值以上的案例占比 (覆盖率) 过低时该类判断没有收益, 不进入下一阶段. 托管 Jev 1.14 用同一批案例作基准: 候选的阈值以上精度与覆盖率不明显低于 Jev 即可进入线上影子阶段, 不要求超过 Jev.

转正阶段 (按 "判断类别 x 实际模型版本 x 题目模板版本" 分别计):

1. 影子: 判断模型照常作答并记录, 动作全部由高智能 Agent 决定; 收集一致率与时长差.
2. 全量复核: 阈值以上的判断直接用于动作, 每一条都由高智能 Agent 异步复核 (复核与撤销的动作合同见 [定义分流判断的复核与回退合同](08-define-routing-review-and-rollback.md)). 进入条件: 离线评测通过, 且影子阶段至少 60 条阈值以上判断无有害分歧 (按 "零错误时 95% 上界约为 3/n", 60 条对应错误率上界约 5%).
3. 抽样复核: 只复核抽样部分, 默认 20%, 每个流程至少复核 1 条. 进入条件: 全量复核阶段至少 100 条, 有害分歧率的 95% 置信上界 (Clopper-Pearson) 不超过 5%, 且该类流程的时长或审核轮数相对对照有改善.

漂移与回退:

- 响应中的实际模型版本, 题目模板或 Engine 组装 `state` 的方式任一变化, 该类判断退回全量复核, 重新累计; 新版本已通过离线评测时, 只需重新满足阶段 3 的条件.
- 滚动窗口 (最近 100 条复核) 的有害分歧率超过 5%, 退一个阶段; 阈值以上的覆盖率与离线评测相差一倍以上, 视为输入分布漂移, 退回全量复核并提示用户.
- 一次需要用户介入才能恢复的判断错误, 该类判断立即退回全量复核.

停止使用: 退回全量复核后再经一个窗口 (100 条) 仍超过 5%, 或连续两次需要用户介入的判断错误, 或在全量复核阶段累计 100 条后该类流程的时长与审核轮数相对对照都没有改善, 该类判断停用, 全部交高智能 Agent, 重新启用需要新的模型版本或题目模板并重新离线评测. 停用不需要用户决定; 重新启用的候选若需要下载或付费, 按本机资源规则另报.

托管评测可发送的内容 (沿用 D3 的默认): 托管 Jev 与其他托管模型只接收取自 ARW 公开仓库的案例, 只用于离线评测; 线上影子与转正阶段在用户的私有仓库中只使用本地候选. 某个托管方案确实需要更多内容时另列待决定事项. 调用记录默认不保存 `state` 原文, 只保存长度, 哈希和来源, 见 [定义 Engine 调用 Jev 类模型的接入方式](16-define-judge-model-integration.md); 离线案例集本身取自公开仓库, 可以保存原文.
