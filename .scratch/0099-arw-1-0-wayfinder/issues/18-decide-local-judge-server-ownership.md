# 确定本地判断模型服务的运行责任

Type: grilling
Status: resolved
Blocked by: issue:0099:16

##### Question

本地 Jev 类候选 (如 Laya, NeoHorse) 以本机 HTTP 服务提供 `/v1/systemone`. 这个服务由用户自己安装并保持运行, ARW 只知道端点 (与托管服务同等对待); 还是由 ARW Engine 按需启动和停止, 并负责与同机其他本地模型 (如 Strata) 分配显卡? 若由 ARW 管理, 是推广现有 Strata 提供方的 lease 机制, 还是另设一套?

## Answer

用户 11-09 分三次答复, 原问题的三个选项 (用户自己运行, ARW 按需启停并推广 Strata 的 lease, 交给 Strata) 都没有原样采用.

选择顺序 (用户原话): "理想情况下, 本机如果能运行判断模型, 那么就取消 strata 的运行, 只运行这个判断模型. 模型选用机器能正常运行, 速度符合要求, 且智能最高的模型. 如果本机没有 gpu, 或是 cpu 模型对 cpu 的消耗过多, 则选用机构内部部署的模型. 上面两条都无法满足, 再退化到使用公开部署的模型."

与 Strata 的优先关系 (用户原话): "总之, 目前我判断, 这个判断模型的价值要高于 strata. 如果结论不是如此, 再改设计."

不退化与启动方式 (用户原话): "首先 "都没有时按 issue 16 交给高智能 Agent" 这个不对. ARW 1.0 肯定是要用判断模型的, 不会退化到交给高智能 agent. 而且我们的判断模型的速度有要求, 必须要让整体的任务执行速度快于不用判断模型时很多. 然后, 判断模型的启动其实就和 strata 一样, ARW 会创建一个开启脚本, 然后在 ARW 工作的时候, engine 会执行这个脚本, 启动判断模型, 这样才能开始正式工作. 没有判断模型, ARW 的 engine 基本无法工作."

11-11 据此定下 "判断模型是 Engine 的必需组件, 不可用时不开工或停在可恢复状态", 并定了本机, 机构内部部署, 公开部署的选择顺序, 由开启脚本启动, 判断模型优先于同机 Strata, 以及 "用判断模型的整体任务执行比不用时快很多" 的端到端验收条件. 11-13 的实验数据正落在用户 "如果结论不是如此, 再改设计" 的条件里, 用户在 D24 中选 A, 本答案 11-14 改写如下 (原结论的去向见 Comments).

判断模型的使用条件 (用户原话, 11-13): "判断模型能用的另一个条件, 是它的处理速度要比 deepseek flash 这类模型快很多倍, 而且准确率也明显降低. 不满足这个要求, 那么就没有必要用判断模型." 用户随即更正: "上面写错了, 是准确率不明显降低".

因此:

- 判断模型可选 (D24, 推翻 11-11 的 "必需组件"): Engine 不依赖判断模型也完整工作; 未配置或不可用时照常工作, 不出提示, 也不为此打断用户; 配了只做提示 (见 [定义分流判断的复核与回退合同](08-define-routing-review-and-rollback.md)). 原 "Engine 不开工" 与 "停在可恢复状态" 的失败点全部删去, 失败处理见 [定义 Engine 调用 Jev 类模型的接入方式](16-define-judge-model-integration.md).
- 使用条件: 判断模型要比托管小模型 (DeepSeek flash 一类) 快很多倍, 且准确率不明显降低, 否则不用. 以 E3 判断题集离线评测 (题集见 [本地 Jev 类候选的可行性小实验](15-task-local-candidate-feasibility.md), 评测方法与启用门槛见 [定义 Jev 类模型的评测与启用条件](11-define-evaluation-and-graduation.md)). 11-13 的 E3 结果: 本机 GLiDE-9B 单次延迟 p50 0.56 秒, DeepSeek flash 1.17 秒, 只快约 2 倍; 同一 222 道公开题上准确率 0.739 对 0.766; 分流题的有害方向漏判 15/30 对 12/30. 不满足条件, 所以 1.0 首版实际不配判断模型.
- 首版的部署: 用户要用时只需在配置中给出一个端点 (可不配), 见 [确定判断模型与兼容端点的安装与配置](20-decide-installation-and-configuration.md). 本机安装, 开启脚本, 显卡探测与 Strata 让出推迟到有满足使用条件的模型时, 写在 20 的 When a qualified local model exists 节; 届时沿用用户 11-09 的选择顺序 (本机能正常运行, 速度达标的候选中智能最高的 → 机构内部部署 → 公开部署, 公开部署由用户明确开启) 与 "判断模型优先于同机 Strata", 两者由那时的数据重新核对.
- 验收: "用判断模型的整体任务执行比不用时快很多" 不再是 1.0 的端到端验收条件 (D24); 1.0 验收对照现行 ARW (11).
