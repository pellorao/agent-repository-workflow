# 确定 Jev 类模型在流程中的职责边界

Type: grilling
Status: resolved
Blocked by: issue:0099:02

##### Question

Jev 类模型在 Engine 驱动的流程中承担哪些判断: 任务分流 (自己判断还是交高智能 Agent), 有明确检查项的预检, 最终输出的语义要求检查; 它是否可以担任正式 Reviewer Role 或其中某一审核轴? 它的判断在什么条件下可以直接触发动作, 什么条件下只作建议?

## Answer

用户 11-07 选择: Jev 类模型不担任任何正式 Reviewer Role, 也不担任其中任何审核轴, 只做三类判断: 任务分流 (判断一件事由谁处理, 适合时自己作答), 有明确检查项的预检, 最终输出的语义要求检查. 正式审核结论仍只来自高智能 Reviewer. 理由来自 [核对 Jev 类判别模型的能力与候选](02-research-jev-class-models.md): confidence 只衡量分布集中度而未在 ARW 文本上校准, 中文能力没有一手证据, 每请求 64k token 上限.

同日用户对托管服务的答复也约束这三类判断的候选: 托管 Jev 只做基础的速度与准确率测试, 作为评估本地候选和其他托管替代方案的基准, 以后大概率不作为正式方案; 正式方案优先在本地模型和其他托管替代方案中找. 评测托管服务时默认只发送 ARW 公开仓库中的案例, 私有内容只给本地候选.

判断在什么条件下可以直接触发动作, 什么条件下只作建议, 属于 [定义分流判断的复核与回退合同](08-define-routing-review-and-rollback.md) 的问题, 本 issue 不作规定; 唯一的前提是预检和输出检查的结论不能替代正式审核结论.
