# Commit Audit prepare 输出实测体积和下一个 ADR 编号

## Problem Statement

实施提交前, Main Agent 在 issue 的 `## What to build` 写体积预算, 在 `## Validation` 或 `## Comments` 写实测净增. 效率规则规定: 改代码的任务按非测试代码的行数计, 改文档的任务按文档字符数计. 这些数字靠手算, 计入哪些文件, 行和字符怎么数都由作者自己判断, Reviewer 用另一种口径复算就得到不同数字, 于是问题被提出, 作者修改记录, 再复审一轮. 近期 92 轮提交审核中, 约 237 条问题里有 37 条是体积数字对不上, 26 轮只有预算或记录文字问题. 新 ADR 的编号同样靠作者查目录, 容易写错, 或与同一候选里已暂存的新 ADR 冲突. 这些事实都能由已暂存候选和 HEAD 机械得出, 不需要判断.

## Solution

`arw commit-audit prepare` 照常新建审核轮, 标准输出仍然只打印轮目录绝对路径; 另在标准错误输出一段候选体积摘要和下一个 ADR 编号. 作者写 issue 记录时把摘要中的数字原样复制, Reviewer 按同一口径复算得到相同结果.

摘要只是诊断信息: 不写入 `request.json`, 不进入 Reviewer 交接, 不改变任何关卡, `verify` 也不检查 issue 中的数字. 数字只由已暂存树和 HEAD 决定, 同一暂存状态重复运行结果相同, Reviewer 只用受审树和 HEAD 就能复算.

摘要放在标准错误, 因为调用方把标准输出当作轮目录路径使用 (例如 `cat <轮目录>/*.jsonl`), 多出的行会破坏这种用法; Spec Readiness 的 `prepare` 已经把警告写在标准错误, 这里沿用同样的分工.

## User Stories

1. 作为 Main Agent, 我希望 `prepare` 直接给出已暂存改动的非测试代码净增行数和文档净增字符数, 以便把准确数字写进 issue, 不必手算.
2. 作为 Main Agent, 我希望摘要逐个列出被计入的文件及其净增, 以便在 issue 里说明哪些文件 (例如生成的镜像副本) 在数字之内.
3. 作为 Main Agent, 我希望知道下一个 ADR 编号, 以便新 ADR 不重号, 也不与同一候选里已暂存的 ADR 冲突.
4. 作为 Reviewer, 我希望 issue 中的数字能用同一口径复算, 以便不再为数字口径提出问题.
5. 作为依赖 `prepare` 标准输出的调用方, 我希望标准输出仍然只含轮目录路径, 以便现有用法不被破坏.

## Implementation Decisions

### What is measured

摘要在 `prepare` 读取已暂存候选之后产生, 比较对象是已暂存索引相对 HEAD, 只描述本次候选. 一个 issue 分多次提交交付时, 每次提交的摘要只覆盖该次候选, 作者把各次数字相加作为 issue 的实测净增. 先取候选中发生变化的路径, 去掉 `.scratch` 下的全部工作记录 (issue, spec, 就绪记录, effort 的 `prototype/**` 和 `research/**`), 因为它们不是交付内容. 子模块 gitlink 没有文本, 不计. 剩下的路径按下列顺序归入第一个匹配的类别:

1. 测试: 路径含目录段 `test`, `tests` 或 `__tests__`, 或文件名在扩展名之前带 `.test` 或 `.spec`.
2. 文档: 扩展名为 `.md`.
3. 代码: 其余所有路径.

每个路径的净增是已暂存版本减 HEAD 版本; 新增文件的 HEAD 版本为空, 删除文件的已暂存版本为空, 重命名按删除旧路径加新增新路径计. 代码和测试按行数计 (按换行符分行, 结尾的换行不多算一行), 文档按字符数计 (Unicode 码点数, 含换行). 删除多于新增时净增为负.

摘要先逐个文件列出 `类别, 路径, 净增`, 再给出三类各自的合计和文件数. 效率规则只要求其中一类入预算 (改代码的任务取非测试代码行数, 改文档的任务取文档字符数), 测试合计仅供参考, 摘要不替作者选择类别, 也不比较预算.

### Next ADR number

下一个 ADR 编号是已暂存树中 `docs/adr/` 下形如 `NNNN-<slug>.md` 的文件的最大 `NNNN` 加 1, 补零到四位; 没有这类文件时为 `0001`. 已暂存的新 ADR 计入, 所以候选已含 ADR 时给出的是再下一个编号.

### Failure and compatibility

摘要只读取候选里已经取得的字节, 不增加 Git 读取, 也没有新的失败来源: 字节按 UTF-8 宽松解码, 非法序列不使 `prepare` 失败. 候选没有计入的文件时三类合计都是 0. `prepare` 对输入, 授权范围和候选的拒绝条件, 轮目录, `request.json` 和 Reviewer 交接都不变; 标准输出的内容和格式不变.

## Testing Decisions

在 Commit Audit 的现有测试夹具上制造一个同时含非测试代码, 测试, Markdown 文档, `.scratch` 记录和已有 ADR 的暂存候选 (含一次删除或缩短, 使净增有正有负), 观察 `prepare` 返回的摘要: 各类合计与文件列表, `.scratch` 记录不出现, ADR 编号为已暂存最大编号加 1. 这能防止口径漂移 (把记录或测试算进预算) 和计数错误 (行与字符混用, 删除不扣减). 再通过 CLI 入口观察标准输出仍然只是轮目录路径, 摘要出现在标准错误, 防止破坏依赖标准输出的调用方. 数字计算是对内存中候选的纯运算, 不需要更多真实进程, 所以不另设单元测试.

## Out of Scope

- 不改变关卡语义: 不校验 issue 里的数字, 不拒绝超预算, 不把数字写进 `request.json` 或 Reviewer 交接.
- 不应用 `.arwignore`, 因为它取自工作树, 会让数字依赖未暂存的状态, 使 Reviewer 无法只用受审树复算; 也不识别锁文件, 生成文件或镜像副本 (例如多处同步的 Skill 副本); 它们按路径类别照常计入, 逐文件列表让作者能在 issue 里说明.
- 不增加配置项, 命令选项或新的子命令.
- 不输出下一个 effort 编号等其他派生值.

## Module Design

### Modules

`Commit Audit Module` 在现有的候选读取, 授权校验和审核轮准备之外, 新增一项只读责任: 从同一份已读取的候选计算体积摘要和下一个 ADR 编号. 不新增 Module, 也不改变它不判断语义, 不选择暂存范围, 不写受 Git 跟踪文件的边界.

### Interfaces

`prepare` 的结果在轮目录之外增加一个多行文本摘要. 命令入口把轮目录写到标准输出, 把摘要写到标准错误. 命令用法, 输入文件和退出码不变.

### Seams and Adapters

不新增 Seam 或 Adapter. 摘要是对内存中候选对象的纯计算, 不增加 Git 或文件系统访问.

### Dependencies and Data Flow

Git 索引和 HEAD 经 Repository State Inspector 一次读取为候选 (现有), `prepare` 用该候选计算摘要, 随结果返回, 命令入口写标准错误. 依赖方向不变, 摘要不写入任何文件.

### Module Design Rationale

选择放在 `prepare` 而不是新子命令, 因为作者记录数字的时刻正好是准备提交审核的时刻, 额外子命令是一个要记住且常被跳过的步骤. 选择标准错误而不是标准输出或 `request.json`: 前者会破坏把标准输出当路径用的调用方, 后者让数字进入 Reviewer 的输入, 使它从辅助信息变成审核对象. 把计算放在 `Commit Audit Module` 而不是 `Repository State Inspector`: 后者只一次取得并提供仓库事实, 不解释它们, 而三类归属与计数口径是效率规则在提交审核里的解释, 属于 Commit Audit 的政策; 为约 30 行纯计算另设独立单元没有第二个调用方, 只增加一层转发. 不应用 `.arwignore` 也比较了第三种方案, 从已暂存树读取同一 `.arwignore` 再自行匹配: Git 的忽略匹配只读工作树, 要在受审树上复现就得自带一套 `.gitignore` 语法匹配或临时索引, 对一段诊断输出代价过高. 接受的成本是: 被 `.arwignore` 匹配但已暂存的文件 (例如固定的测试夹具) 会进入摘要, 与 Code Standards 审核范围略有差异, 逐文件列表让作者看到并在 issue 里说明. 测试, 文档, 代码三类的路径启发式不识别每个仓库的布局, 接受这一局限, 因为摘要不是关卡, 逐文件列表让作者能发现并说明误分类.

### ADR Evaluation

权威来源不变: 体积和编号只由 Git 索引与 HEAD 派生, 不是新的权威. 不增加持久状态, 摘要不落盘, 重新运行即重新计算; 没有新的恢复合同, 也不改变 `docs/adr/0023-separate-commit-audit-review-from-implementation.md` 中审核与实施分离的选择. 输出只是可随时撤销的诊断文字, 不需要新 ADR.
