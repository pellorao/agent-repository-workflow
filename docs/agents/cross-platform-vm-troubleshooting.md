# 跨平台 VM 故障排查

## Troubleshooting the maintained automation

应用只适用于发布的补偿前, 保留原始失败步骤. 使用下列条目诊断受维护的脚本. 它们描述已经修复的失败类别, 不得作为新策略复制到本地驱动程序.

决定哪些工作可以继续前, 对失败进行分类:

| 类别 | 含义 | 发布后果 |
| --- | --- | --- |
| 候选内容失败 | 未变更的候选内容或其已跟踪发布维护代码违反预期步骤合同 | 保留正式失败, 完成独立发现路径, 在新提交中修复, 并从第 1 步重新开始完整的 `pre-tag` 流程 |
| 环境失败 | 主机, 来宾系统, 虚拟机监控程序, 网络, 凭据, 运行时或基线状态阻止正式步骤, 且没有证明候选内容存在缺陷 | 保留失败或不可用路径, 修复环境, 并重新运行每条受影响的正式路径. 它不能产生通过结果 |
| 诊断补偿 | 安全, 最小且明确标记的只适用于发布的变通办法, 用于揭示后续独立的候选内容行为 | 把所有输出保留在当前会话工作区中. 不得最终化经过补偿的步骤, 也不得把它包含在归档中 |
| 正式证据 | 每个已注册步骤都在没有补偿的情况下, 对一份未变更且已经提交的候选内容运行, 并产生已接受的规范输出 | 只有规范归档可以为 Release Conformance 提供证据. 旧失败, 诊断归档和补偿输出绝不成为正式证据 |

| 症状 | 原因 | 解决方法 |
| --- | --- | --- |
| Windows 工作区准备拒绝有效的目标路径 | 调用 `New-Item` 时使用了该目录创建路径不支持的参数 | 使用 `New-Item -ItemType Directory -Force -Path <path>` |
| Windows `node -e` 收到的脚本中, 带引号的路径变成不带引号的驱动器路径 | SSH 在 PowerShell 前进入 Windows 命令解释器, 因此嵌套双引号在受到 PowerShell 单引号参数保护前已经被使用 | 把完整 PowerShell 调用编码为 UTF-16LE, 并使用 `powershell.exe -EncodedCommand`. 在确定性测试中解码该载荷, 并要求原始参数数组 |
| Windows 安装文件和清单匹配, 但 `windows-user-path.json` 被报告为意外变更 | 完整 Installation 预期省略了测试自有的 PATH 观察, 即使 Installer 已经正确注册其负责的项 | 根据先前的 PATH 观察和 Installation 目录推导预期存储值, 值类型, 实际项和精确的清单责任归属. 把最终观察字节与命令执行后捕获的内容进行比较 |
| 直接执行的 ESM CLI 在路径包含 URL 敏感字符时以 0 退出但没有输出 | 主模块检查手动拼接文件 URL | 比较 `import.meta.url` 和 `pathToFileURL(process.argv[1]).href` |
| 第一个来宾系统步骤在没有 `HEAD` 的仓库中挂起 | 空树哈希计算打开了从未收到确定性 EOF 的输入 | 在仓库 Git 目录下创建空的临时输入, 并把它传给 `git hash-object -t tree` |
| PowerShell 同时找到 `arw` 和 `arw.cmd` | 命令发现为一个已安装启动器返回多个应用名称 | 把 `Get-Command arw -All -CommandType Application` 过滤到精确的已安装 `arw.cmd` 路径, 并要求只有一个结果 |
| Windows 报告 `spawn EINVAL` 或丢失包含空格的启动器路径 | `.cmd` 文件不是可以直接执行的进程目标, 且普通参数引用可能被 `cmd.exe` 重新解释 | 把精确的启动器路径放入专用子进程环境, 运行一条逐字的 `cmd.exe /d /s /c call` 命令, 并保留真实的退出代码和流 |
| 初始化, 删除或重新初始化拒绝在其他状态中有效的选项 | 驱动程序在适用的 Scenario Plan 操作之外重放选择 | 在下次正式运行前修复 Registry 或计划映射. 不得使用猜测的参数重试失败步骤或添加逐步骤预检. 第一次初始化使用固定的目标特定转换选择, 重新初始化省略转换和孤立项选项, 删除只包含已注册类别 |
| 每个仓库场景都在第一次初始化时因 CLI 用法失败 | 来宾系统辅助程序把 `--dry-run` 附加到初始化或删除命令, 但公开 CLI 只为更新支持模拟运行 | 在 `beforeApply` 从已安装的 Workflow Module 捕获精确的稳定计划, 使用与实际子进程相同的隔离主目录和平台环境事实. 然后不使用 `--dry-run` 运行已注册的公开 CLI 命令 |
| Workflow 计划捕获只报告没有到达 `beforeApply` | 辅助程序丢弃 Workflow Module 的封闭结果, 并隐藏其诊断代码 | 来宾系统失败摘要中只包含有界的诊断代码集合. 更改 Registry 选择或产品行为前检查这些代码 |
| 已准备的仓库场景通过第一步, 但在执行前拒绝下一步 | 来宾系统准备过程把第一步选择保存为场景身份, 即使选择按步骤冻结 | 使用只包含可复用场景身份和路径的来宾系统准备模式版本 2. 继续把每次调用的选择与当前 Registry 步骤进行比较 |
| 删除捕获成功, 但机械评估拒绝计划结构或 `delete-lock` | 评估程序把初始化或更新计划模式应用于原生删除计划, 或把 Workflow Module 内部的锁后置顺序操作公开为新的文件操作 | 验证原生删除的 `{categories, choices, diagnostics, operation, operations}` 结构, 并在有限评估前把 `delete-lock` 投射为同一路径的有序 `delete` |
| 初始化, 更新或重新初始化捕获成功, 但机械评估拒绝 `write-lock` | 捕获的 Workflow Module 计划把其内部锁后置顺序操作公开为第三种文件变更 | 在有限评估前把 `write-lock` 投射为同一路径和字节的有序 `write`, 与删除的 `delete-lock` 投射对称 |
| Code Map 验证报告 Registry 列出的预期问题, 却被视为失败 | 通用仓库验证合同要求退出 0, 而不是使用已注册的预期结果 | 在 Registry 中绑定精确退出代码和有序标准错误预期, 并且在不根据虚拟机或场景身份分支的情况下评估该记录 |
| Git 状态报告同一路径已暂存的删除和未跟踪的重新创建 | 机器可读输出对一个逻辑最终路径包含两个事实 | 把该配对项合并成一个 `modified` 判断项, 同时在未跟踪内容中保留重新创建的字节. 拒绝其他每种重复路径组合 |
| 后续机械步骤拒绝先前步骤已经接受并暂存的路径 | 步骤评估程序把当前差异与累积的 `HEAD` 到 Git 索引模板进行比较, 仿佛每条已暂存路径再次发生变化 | 在结果中保留每条模板路径. 把当前判断应用于当前路径, 并把未变更且已经接受的 Git 索引基线标记为 `retained` |
| 保留配置或未知内容时, 卸载操作把每项受管理删除报告为不匹配 | 转换过程复用场景最终清理预期, 该预期要求没有测试残留 | 独立评估卸载操作. 要求删除每条由清单管理的路径和清单, 应用已注册的配置选择, 逐字节保留已经注册的未知内容, 并恢复平台 PATH 或配置基线 |
| 清理测试残留后, 最终状态验证发现原本应为空的 Installation 目录 | Uninstaller 正确保留未知测试文件, 后续有限清理 unlink 最后一个文件, 但没有删除现在已经为空的精确父目录 | Unlink 已验证的测试文件后, 重新验证精确父目录是普通目录, 并且只在它为空时使用非递归 `rmdir` 删除. 保留每个非空父目录和剩余项 |
| Release Conformance 抛出异常或返回格式错误的对象, 并泄露异常 | CLI 在没有规范验证的情况下信任运行时结果 | 把失败转换为一条有序运行时诊断信息并以 1 退出. 绝不把格式错误的成功对象视为通过 |

如果执行所列修正后症状仍然存在, 在当前会话工作区中捕获精确命令, 退出代码, 可用流和相关机械事实. 不得把主机路径, 虚拟机身份, 凭据或复制的本地配置添加到已跟踪 issue 或文档中.
