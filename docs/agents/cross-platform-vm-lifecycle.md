# 跨平台 VM 生命周期

## Routine lifecycle

Release Validation Module 按以下顺序执行每个已注册的发布场景. 不得在每个步骤前手动重复这些检查.

1. 在第一个场景使用该虚拟机前, 验证已配置的 VMX 路径, 精确快照身份, 虚拟机类型, 主机可执行文件, 凭据结构和 Node.js 可执行文件字段.
2. 对于每个场景, 读取电源状态, 必要时执行硬关机, 读取快照, 要求使用已配置的快照, 还原到该快照, 并验证关机状态和当前快照身份. 不得读取, 保存或比较虚拟磁盘链. 不得复用其他场景的来宾系统状态.
3. 在主机上检查每个 Registry 要求的已准备捆绑包. 候选内容来自按[源码仓库发布验证](source-checkout-release-validation.md#local-candidate-loop)创建的干净且已经提交的隔离本地 Repository, 两个目标的当次临时提交来自已准备的本地源码 bundle, 不来自根配置的固定原提交. 如果治理 issue 允许, 快速的非发布迭代仍可使用项目特定的临时输入.
4. 在后台启动 VM, 并等待使用严格固定主机密钥的 SSH 或已配置的 Windows 远程管理通道. 验证 OS, 架构, 时间, 工具, Git, 每个已配置的绝对 Node.js 可执行文件, 以及干净的项目状态.
5. 传输 Git 捆绑包和内部来宾系统辅助程序. 只能从这些本地捆绑包克隆或签出. 来宾系统不执行远程 Git 操作, 也不下载 Bootstrap 或 Agent CLI. 确认候选版本标签不存在, 只为本次验证在精确候选提交上创建该本地标签, 且绝不推送.
6. 以独占方式创建场景特定的工作, 主目录和受审仓库路径. 初始化 Git 和 `git add -A` 比较基线. 来宾系统准备模式版本 2 精确包含 `{commit, fixturesDirectory, homeDirectory, installationAuditDirectory, machineKey, scenarioId, scenarioRoot, schemaVersion, sourceDirectory, tag, targetDirectory, targetKind}`. 只保存可复用的场景身份和这些路径. 不得把第一个步骤的选择绑定到该记录. 选择仍由每个冻结的 Registry 步骤负责. 不要求提交.
7. 运行一个封闭的 Registry 步骤, 并捕获完整状态, 两份已跟踪二进制差异, 未跟踪普通文件字节, 非普通项类型, 实际子进程结果和可用流. 在初始化, 更新, 删除或重新初始化修改前, 使用与 CLI 相同的隔离主目录环境事实加载已安装的候选 Workflow Module, 捕获其稳定计划后在 `beforeApply` 停止. 不得调用不受支持的公开 `init --dry-run` 或 `remove --dry-run`. 如果 Workflow Module 在 `beforeApply` 前返回封闭失败, 在有界失败摘要中保留最多 8 个已经排序, 唯一且格式有效的诊断代码, 不复制诊断消息或计划字节. 保留原生初始化或更新计划结构. 保留原生删除类别和选择. 把内部锁顺序操作 `write-lock` 和 `delete-lock` 投射为有限合同中对同一路径的普通 `write` 和 `delete` 操作. 自动应用已经注册的有限机械合同. 只有 Registry 标记了相应操作时, 才创建 Main Agent 语义操作和判断交接. 预期不匹配会成为正式失败. 不得重新检查场景选择, 也不得使用猜测的参数重试.
8. 运行已经注册的功能最终状态比较. Windows 保留原始逻辑 `Path` 单元和顺序, 同时允许归一化末尾分隔符. Linux 删除 ARW PATH 行为, 保留原始内容和顺序, 并且在基线不存在或为空时, 允许最终 `.profile` 不存在或为空.
9. 把每份可用的审查字节和归档来源字节取回当前会话工作区. 只有场景清理成功后, 主机 Archive Module 才创建并验证规范 tar. 不得在来宾系统中创建归档, 也不得把传输哈希保存为发布证据.
10. 通过已配置的虚拟机操作对来宾系统执行硬关机, 并验证它已经关机. 只有场景本身要求时才使用 `soft-power-off` 或重启来宾系统. 有界软关机超时恢复和 Registry 对该结果配置的任何接受规则都不会改变默认的硬关机路径.
11. 还原到指定名称的基线快照.
12. 验证关机状态, 并重新读取当前快照指针. 如果已配置的快照还原成功, VM 已经关机, 且当前快照身份与配置值完全相同, 清理通过. 不得读取, 保存或比较虚拟磁盘链. 这些 VM 清理事实保留在发布归档之外.

清理通过前, 不得启动下一个使用同一虚拟机的场景, 也不得最终化其归档. 不得为了方便而让来宾系统保持运行. 不得通过删除来宾系统测试文件替代回滚. 回滚是防止一个场景或项目污染另一个场景或项目的责任边界.

## Candidate provenance

可以把工作树文件复制到 VM 进行快速迭代, 但这不能授权发布.

发布生命周期验证的候选创建, 解析和捆绑包准备统一遵循[源码仓库发布验证](source-checkout-release-validation.md#local-candidate-loop). 主机从隔离本地 Repository 取得准确候选内容, 验证期间不向规范远程推送候选分支或版本标签. 每个来宾系统只从主机提供的捆绑包签出精确候选提交, 在该提交上创建仅用于本地验证的版本标签, 并使用该标签运行根 `install.mjs`.

签出操作选择字节. 不得把签出提交, 树, 基线, 变更路径, Source Checkout 文件清单, 捆绑包身份或内容摘要值保存或比较为 Installation 证据.

Source Checkout 发布流程把完整候选内容保留在内存中, 并在每次来宾系统签出交接前以及每个场景返回后重新解析它. 来宾系统不保留该 Git 身份. 如果流程丢失初始候选内容或无法证明比较连续未中断, 之前的任何场景归档都不能授权恢复发布. 对当前候选内容重复每个 `pre-tag` 场景.

合成测试夹具标签用于证明安装, 修复, 升级和降级机制. 其来源文件或生成程序在 Source Checkout 中保持已跟踪, 来宾系统在运行时创建相应的临时仓库和标签. 不得保留来源归档或测试夹具 Git 身份. Release Validation Registry 负责精确的生命周期轴和归档清单. Runner 负责的机械判断和 Main Agent 编写的语义初始化判断属于发布证据. 不得添加其他证据 JSON 或归档摘要值绑定.
