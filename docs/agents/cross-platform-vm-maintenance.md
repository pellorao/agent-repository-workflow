# 跨平台 VM 维护和证据

## Baseline maintenance

把每个共享基线快照视为不可变. 常规项目授权允许以下操作:

- 启动来宾系统.
- 为测试修改来宾系统.
- 导出证据.
- 硬关机和回滚.

只有已经验证的场景有此要求时, 才使用来宾系统软关机或重启. 常规授权不允许创建, 替换或删除快照, 自动升级操作系统, 替换共用工具链, 更改固件, 升级虚拟硬件, 更改磁盘控制器或网络模式.

基线维护需要用户明确授权. 授权后, Agent 应执行 VMware 和来宾系统自动化能够安全完成的每项操作. 只有确实需要控制台交互或其他不可用能力时, 才请用户操作.

对于已授权的替换:

1. 记录旧快照名称, 并验证它是当前快照且已经关机.
2. 从旧基线启动, 只执行已授权的共享变更, 并保留每项软件包和配置变更的审计.
3. 验证远程访问, 工具, 安全状态, 更新策略, 时间同步, 以及至少两次连续的温重启.
4. 正常关机, 断开安装介质, 并创建带版本和日期的新快照.
5. 启动并验证新快照, 关机, 然后再次还原.
6. 向用户提供新旧身份和证据.
7. 只有在用户明确确认替换后, 才删除旧基线.

不得把项目测试运行复用为隐式基线更新. 除本指南声明的共享账户以外, 不得保留项目特定的 SDK, 仓库, 缓存, PATH 项, 服务, 计划任务, 命令解释器历史记录, 软件包归档或测试账户.

## Evidence and rollback

把证据放在发起请求的 Agent 的 ARW Engine 管理 `.tmp/<agent-platform>/<sessionId>/` 目录下, 适用时使用 issue 和用途层. 如果平台无法提供必要身份, 停止. 发布证据使用规范未压缩 POSIX ustar 和 Release Conformance 要求的固定路径.

每个归档根目录只包含 `summary.json` 和 `steps/`. 内容结构如下:

- 根目录摘要字段精确为 `matchesExpected`, `steps` 和 `summary`.
- 每个步骤包含 `validation.json`.
- 命令步骤精确具有 `exitCode`, `files`, `matchesExpected` 和 `summary`, 以及实际可用的每个 `stdout.txt` 或 `stderr.txt`.
- 非命令的有限操作或语义步骤精确具有 `files`, `matchesExpected` 和 `summary`, 且没有输出文件.
- 每个文件判断精确具有 `changeType`, `matchesExpected`, `path` 和 `summary`.

只保存变更路径, 不保存完整差异或未变更清单. 完整差异和未跟踪字节是临时审查输入, 不是归档内容. 文件判断为 `false` 会使相应步骤为 `false`, 步骤为 `false` 会使根目录为 `false`.

归档不包含内部清单, Bootstrap 辅助程序, 候选来源, Git 身份, 来宾系统事实, VM 清理事实, 完整差异, 归档摘要值, 运行状态或独立证据 JSON. 场景清理后, 主机 Archive Module 创建 tar 并对其执行来源验证. 不得复制来宾系统创建的归档或保存传输摘要值. 关机, 快照还原, 关机状态和当前快照检查仍属于验证后的普通 VM 清理. 回滚成功后, 只删除不再需要且由项目负责的主机临时脚本. 绝不把其他项目的证据或共享主机密钥资料作为清理内容删除.
