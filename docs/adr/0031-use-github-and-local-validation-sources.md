# 使用公开 GitHub 来源和本地验证源码

ARW 使用根发布配置指定的公开 GitHub HTTPS 来源, 安装者无须私有 GitLab 权限或 SSH 密钥. Bootstrap 仍只安装准确稳定 tag 对应的提交; 没有稳定 tag 时使用源码安装, 不隐式回退到默认分支. 规范地址只保存在根发布配置, 生成物继续由该来源派生.

发布验证的两个目标使用维护者在仓库外管理的源码目录, 独立外部 JSON 只保存目录位置. 不要求原项目 Git 历史或固定原提交. 准备时复制当前内容并建立临时 Git 基线和 bundle, 让同次运行跨 VM 使用相同输入, 并继续执行真实 Git 工作流检查. 临时提交只标识该次材料, 不证明原项目身份. 位置, 配置和源码不进入版本管理或发布证据. 原始目录不被修改, VM 配置的职责和格式保持不变.

后续托管发布使用维护环境认证的外部 `gh`, 消费已经验证的准确 tag, commit 和用户批准的公告文件. 先读取既有对象, 只在明确不存在时创建, 再读回核验; 冲突或结果不明确时保留 tag 并停止, 不自动更新, 删除或盲目重试. ARW 不新增 GitHub HTTP 运行时, 凭据管理或远端发布状态文件. 这些责任由外部工具承担, 项目保留候选与发布判断.

用户可以只把当前源码文件快照建立为新的 Git 历史, 不引入原提交, 分支或 tag. 源码迁移不等于正式发布; 没有较早稳定版本时, 现有正式验证所需的旧版输入仍是必须先解决的前提, 不由迁移操作豁免.

本决定取代 [ADR 0024](0024-use-ssh-for-private-gitlab-acquisition.md) 的私有 GitLab SSH 来源政策和 [ADR 0029](0029-use-external-glab-for-gitlab-release-publication.md) 的外部 GitLab 发布工具选择. 保留准确 Git 对象和字节核验, 单一来源配置, 已批准公告交接和失败停点, 以减少维护者需要承担的认证与远端状态责任.
