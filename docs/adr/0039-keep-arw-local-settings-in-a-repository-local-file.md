# 发布验证配置拆成共用机器文件和 ARW 发布配置, ARW 设置放在仓库本地被忽略的文件

本决定补充 `./0031-use-github-and-local-validation-sources.md` 中 "VM 配置的职责保持不变": 配置的职责不变, 本决定规定 VM 配置的格式拆分和 ARW 专用设置的存放位置.

## Context

发布验证需要的 ARW 专用设置 (共用机器文件路径, fixture 目录路径, 每台机器的 Node.js 路径) 此前和机器信息一起放在维护者位于仓库外的单个 VM JSON 里, 每次发布验证还要询问维护者该文件的路径. 用户 2026-11-03 要求: 这些路径记录在工程里一个只属于 ARW 仓库, 不属于 ARW 安装物, 并被 Git 排除的文件里, 其他只在 ARW 仓库工作时需要的本机配置也放在这里, 而不是 VM 目录; 秘密只留在共用机器文件.

## Decision

- 仓库根的 `.arw.local.json` (被 `.gitignore` 排除) 是 ARW 源码仓库本机设置的持久权威位置, 按用途分对象, 发布验证使用其中的 `release` 对象. 它只保存路径和 ARW 自己的设置, 不保存秘密, 不进入版本管理, 发布证据或安装物, 也不是根目录 `/config.json` (安装后的用户数据) 或 `config.install.json`.
- VM 配置拆成两部分: 仓库外的共用机器文件 (机器信息和秘密, 本机其他工具也读取) 和 ARW 发布配置 (`release` 对象, 或 `--config` 指定的文件), 后者用 `sharedMachinesConfig` 路径引用前者.
- 按机器键浅合并: ARW 条目的顶层键逐键整体覆盖共用条目的同名键, 不深合并. 只跟随一层引用, 共用文件里的 `sharedMachinesConfig` 和顶层键被忽略.
- 没有 `sharedMachinesConfig` 的单文件完整配置继续有效, 无需迁移.
- 格式和合并规则的细节由 `$release` Skill 的 `references/vm.md` 拥有.

## Rejected alternatives

- 放在 VM 目录 (原做法, 一个 `arw-release/` 配置文件): ARW 设置与仓库脱节, 要靠路径才能找到, 每次仍需询问路径; 用户已明确要求不放在 VM 目录.
- 放在仓库外的其他固定位置 (用户目录或环境变量): 与仓库没有同生命周期, 换工作副本时含糊, 也不满足 "记录在工程里".
- 深合并或递归跟随引用 (格式方面): 覆盖语义含糊, 需要循环检测和更多错误路径, 当前没有需求; 浅合并的成本是覆盖对象值 (如 `ssh`) 必须整体给出, 共用文件之后对该对象的修改不被继承.
- 仓库本地被忽略的文件: 路径是本机事实, 与仓库同生命周期, 一次记录后不再询问. 接受的成本: 每个工作副本各自写一份, 脚本从仓库外复制出去使用时需要 `--config`.

## Consequences

ARW 条目覆盖对象值时必须整体给出该对象; 共用文件不能再引用别的文件. `.gitignore` 必须排除该文件, 文件内容只含路径和 ARW 设置. 以后其他 ARW 本机设置放在同级对象中, 不新增文件.
