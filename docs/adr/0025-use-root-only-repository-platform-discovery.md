# 只从 Repository 根发现平台定义

## Context

仓库工作流从最近 Git 仓库根开始, 但过去会递归查找任意深度中形状相同的平台定义目录. 这种做法试图一次覆盖单仓库多项目布局和嵌套项目, 却让外层仓库解释不属于自身工作流权威范围的子项目和 Engine 临时状态. 按被忽略路径或特殊目录逐项排除, 只能继续扩大隐含规则, 不能说明谁负责初始化嵌套项目.

## Decision

一次仓库工作流操作只从最近 Git 仓库根下读取当前平台声明的准确相对路径, 不递归发现普通子目录或嵌套 Git 仓库中形状相同的平台定义. 一个嵌套仓库需要 ARW 工作流时, 用户从它自己的根目录单独执行工作流操作, 由该仓库独立拥有 Repository Profile, 锁文件, 冲突检查和受管内容.

## Consequences

外层仓库不再替嵌套项目发现或判断 Agent, Skill 和平台配置冲突, 即使平台运行时本身支持某些嵌套发现行为. 该限制使工作流读取范围与仓库权威范围一致, 避免把临时快照或工具目录误认为当前项目定义, 并以一条准确路径规则取代递归枚举和不断增加的排除规则.
