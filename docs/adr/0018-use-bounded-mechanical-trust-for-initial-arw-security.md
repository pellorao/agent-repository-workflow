# 首期使用有界机械信任边界

## Context

ARW 需要取得外部来源, 安装 Engine 并更新 Repository Workflow Distribution. 它可以验证已配置输入和精确字节, 但若要进一步证明提交作者, 托管账户或发布权威, 就必须建立签名策略, 受信任密钥生命周期, 身份提供者集成和相应恢复流程. 这些机制不能由提交哈希本身提供, 也不能替代 Agent 审核和用户采用决定.

## Decision

首期来源获取只接受已跟踪来源配置中显式的 `https://` 或 `ssh://` URL, 以及完整且不可变的提交 ID. HTTPS 覆盖常见公开来源, SSH 覆盖需要凭据的私有来源. 其他协议, 本地路径和简写不会增加首期必须支持的来源情形, 却会扩大解析器, 传输和隐式本地信任面. Git 取得的对象必须匹配提交 ID 和准确字节; ARW 不验证作者, 签名者, 托管账户或物理端点身份.

[ADR 0031](0031-use-github-and-local-validation-sources.md) 定义的本地发布验证目标是有限例外: 仓库外源码目录按当前内容提供测试材料, 不要求原 Git 历史或原提交 ID. 工具为一次准备建立的临时提交只绑定该次传输和检查, 不成为原项目版本或来源信任权威. 已跟踪 Upstream 来源取得和正式 ARW 候选仍保留准确提交要求.

上述完整提交 ID 约束适用于已跟踪来源配置驱动的来源取得. ADR 0020 定义的公开 Bootstrap 安装是明确的有限例外: 用户可以用规范稳定标签选择版本, Bootstrap 经 HTTPS 从规范远端的该标签 release 下载安装压缩包, Installer 验证压缩包内软件包版本与标签一致. 标签不因此成为不可变身份, 该流程也不证明 release 资产不可变; 重新指向标签的风险和恢复边界继续由 ADR 0020 与 Release 验证流程负责.

Source Scope 只选择可移植的常规 Git blob 对象, 保留 `100644|100755` 模式, 使用可跨平台确定性实现的最小有版本路径匹配语法. 符号链接和 gitlink 会引入快照外目标或额外来源身份; 不可移植路径会让在 Linux 上可审核的候选项在 Windows Projection 中失败; 更复杂的路径匹配语法会扩大解析器语义, 却不改善首期 Base/Theirs 选择.

已登记验证器只能是读取所提供字节和元数据的确定性进程内函数. 它们只证明边界明确的机械不变量, 不把自由形式的语义判断伪装成程序证明. Agent 负责完整语义审核, 用户决定是否采用准确候选项. 批准证据不绑定具体 Interface, 因为用户可能无法运行本地 CLI; 工具将决定绑定到修订版本和摘要值, 但不验证外部传输身份.

ARW Release 和 Workflow Distribution 首期不增加签名, 受信任密钥, 轮换, 撤销或在线验证. 用户选择的 Source Checkout 是 Installer 信任根, 已安装的 Engine 是目标更新的信任根. 清单, 版本, 清单和摘要值检查用于发现缺失, 意外损坏和不匹配, 不声称抵抗能够同时修改载荷和验证代码的恶意信任根.

macOS Developer ID 签名, 公证和装订是平台分发要求, 不是 ARW 拥有的签名或受信任密钥子系统. 它让 Gatekeeper 验证 Apple 接受的精确 macOS 记录, 但不改变 Source Checkout 与已安装 Engine 的 ARW 信任根语义, 也不让目标仓库运行时执行在线 Release 验证. 延迟发布 macOS 记录的流水线选择见 ADR 0019.

## Consequences

首期安全工作集中在直接保护产品行为的确定性来源取得, 可移植物化, 精确字节审核和授权绑定. 这减少了没有独立信任权威时收益有限的密钥和身份子系统, 代价是用户必须通过配置审核和选择信任根承担来源身份判断. 若未来需要抵抗恶意 Source Checkout, 已安装 Engine 或托管身份替换, 必须另行设计信任权威和恢复契约, 不能把现有摘要值检查重新命名为签名验证.
