# 低价值测试清理

## Trigger and responsibility

用户主动要求清理低价值测试时使用本流程, 不设置固定周期或自动任务. 先按 `implement` Skill 的 Entry 确认匹配活动 issue, 本次范围和已获授权的取舍. 本规则存在, 普通新增测试或交付清理文档本身都不授权立即删除现有测试.

Main Agent 固定本次基线和目标, 协调准确文件范围, 集成验证及正式审核. 实现者在分配范围内判断价值, 执行已授权删除或优化并记录证据. Git 写入和恢复仍遵循 [文件写入规则](../../../docs/agents/agent-writes.md), 规则及设计修改仍按 `rule-and-design-changes` Skill 取得确认, 不新增清理工具, 任务调度器或报告格式.

## Default scope and goals

用户没有另定范围和目标时, 全面审查当前仓库的测试案例与测试基础设施. 在本次开始时固定普通独立叶子案例基数 N 和准确原案例集合. 叶子是实际承担独立观察的测试回调, 不把只负责分组的父回调再算作一项. 平台条件跳过的普通叶子计入, 纯分组父回调, Reviewer 能力场景的合成夹具案例及无测试声明的辅助文件结果排除. 动态子案例按实际运行口径核对, 分别说明普通声明, 子回调, 排除对象和完整运行总数的关系.

默认至少删除 N 的 20% 并向上取整. N 固定到本次起点, 不随批次递减, 不沿用历史清理的基数或删除数量. 目标只计算实际删除的低价值原案例. 改名, 新增跳过, 移出发现和仅合并回调不能冒充删除. 合并重复矩阵或准备可以降低成本, 但仅减少名称或回调数且保留原观察的操作另记, 不计入实际删除目标.

默认先达到低价值删除目标, 再按剩余套件的最新慢案例排名进行耗时优化, 避免优化随后会被删除的对象. 用户可以为当前清理另定范围或目标, 变更应记录在正式交付要求或验收条件, 不只留在讨论中.

清理任务默认要求同一固定候选在没有其他测试套件并跑时, 连续三次运行目标仓库已有完整测试命令全部通过, 命令启动到退出的墙钟耗时中位数低于 5 秒. 计时包含命令启动及实际测试执行, 不包含审批, 工具等待或测量数据解析, 不使用测试框架内部计时或最快一次代替. 这是可由用户另定的本次清理验收目标, 不是日常测试的自动失败条件, 也不取代仓库单回调阈值.

## Prepare and measure

修改前核对活动 issue, 当前候选, 可恢复基线和分工, 完成本次测试及基础设施范围清单与固定计数. 保存环境, 测量命令和统计口径, 使用现有测试命令, 报告器及必要只读观察, 不新增永久计数能力. 模拟字符串, 合成夹具和真实普通测试应分清, 不只统计源码中测试声明关键字的数量.

取得一次完整套件的当前基线, 记录实际回调及跳过结果, 完整命令墙钟和单回调前 10 名. 测量及后续性能阶段遵循[测试性能优化流程](../test-performance-optimization/SKILL.md#baseline), 重用相同口径的有效结果, 不为清理逐层建立额外测量关卡. 开始删除前的完成标准是范围, 原案例集合, 基数, 目标和实际验证责任均明确, 未解决的重要取舍已交给用户决定.

## Value and authorization

按相对价值排序, 判断案例能发现的实际错误, 独立回归风险, 失败影响及运行和维护成本. 优先删除只复述配置值, 普通文档文字或实现逻辑, 不能发现实际行为错误, 以及已有更小代表充分证明的重复观察. 必须由机器读取的固定格式, 准确授权, 结果和报告绑定具有真实责任, 不因包含字面值就归为低价值.

区分重复覆盖和低风险独立观察. 重复删除指出准确保留案例或表格行怎样承担原责任. 独立观察的减少如实说明具体损失, 不能声称已有案例完全替代. 本次用户明确接受其范围和损失后可以裁减低风险独立观察, 不强制每项都有替代. 已授权批次按准确范围继续, 不逐项重复请求; 新损失或范围扩大先取得必要决定, 不把过去一次清理的取舍自动用于本次.

始终保留权限, 身份, 数据安全, 事务恢复以及正式授权和报告格式及绑定等核心保证, 保持正式运行时行为. 如果在已有授权内无法同时达到删除或耗时目标并保持这些保证, 向用户说明具体冲突, 剩余可行范围和需要调整的目标或取舍, 等待决定. 不为满足比例擅自删除核心覆盖或扩大低风险损失授权.

真实端到端案例按[必要性规则](../validation/SKILL.md#coverage)判断. 日常已执行且没有独立风险的完整流程可以作为低价值候选; 普通工作几乎不触发的关键失败, 恢复或授权情形仍保留必要观察. 单案例新增预先批准不是本流程的要求, 单回调耗时及准确实测例外继续由性能规则拥有.

## Delete and optimize

先按本次批准范围删除低价值原案例和无关重复准备. 对每项记录准确原文件及案例名称, 原观察责任, 相对价值理由, 替代覆盖或实际独立损失, 核心保证留存. 保留数据可以使用现有 Markdown 或结构化记录, 不建立新的固定报告模式. 删除整个回调不产生仍需测量的新回调, 合并或语义调整后的现存回调按性能规则测量.

每批核对原案例集合中实际删除, 恢复和当前存在的项目, 另列新增及改名关系. 对合并矩阵和共享准备分别记录成本变化, 不据此声称原独立案例已删除. 使用当前声明和实际动态运行结果交叉核对, 不只累计早期删除清单; 恢复后以最终候选重新计算净实际删除数.

删除目标达到后, 根据剩余套件最新完整结果判断完整命令目标是否已经满足. 尚未满足时进入[性能优化批次](../test-performance-optimization/SKILL.md#iteration), 按最新慢案例排名优先处理. 回调缩小, 共享准备, 真实边界代表, 语义组合, 批量操作, 定向前后测量和波动处理均复用该流程, 不复制另一套阈值或迭代规则. 低风险独立损失的授权继续按上方责任处理, 耗时下降不能来自未记录损失或绕过正式行为.

清理任务的删除及完整命令目标已经满足, 所有新建或语义修改回调也满足仓库阈值或准确实测例外时, 可以进入最终验收. 未修改的既有慢回调不因排名而自动成为额外优化目标. 当前 issue 另有单案例性能目标时, 仍须完成该目标.

## Verify and handle review

对最终固定候选按 `validation` Skill 取得全部必要结果, 核对实际计数和授权范围, 并按默认或用户另定目标进行完整命令验收. 三次之间及每次运行内的必要来源不变, 没有其他测试并跑. 保存全部结果及真实波动, 不把某次内部计时或更快的试验命令替代正式完整命令.

Main Agent 独立核对 Code Review 提出的覆盖问题. 核心保证误删时恢复或增强必要观察, 重新验证受影响候选, 修正净删除及性能结果, 后续审核按当前版本进行. 不为保住数字而隐藏恢复或牺牲核心保证. 用户明确拒绝低风险覆盖添加时, 记录本次具体损失和取舍, 取消对应未执行任务, 不自行重加或重复请求相同授权.

完成标准是当前候选达到适用删除及完整命令目标, 核心保证和正式行为有效, 每项删除及真实损失可核对, 新增和恢复计数准确, 所有必要验证和适用审核均已取得当前有效结果. 最后按 [issue 生命周期](../issue-tracking/SKILL.md#issue-lifecycle)保存实施证据和真实状态. 单次覆盖拒绝不成为长期规则, 历史直接提交例外不授权省略本次 Spec Readiness, 审核或 Commit Audit.
