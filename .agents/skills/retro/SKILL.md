用户要求做一次 **复盘**. 你要为编码 Agent 的 **环境** 提出改进建议, 使以后的运行更好.

## Steps

1. 使用 `$writing-for-agents` Skill 获取写作风格指南.

2. 阅读用户指定会话的一手资料, 这可能需要在本机搜索会话日志. 用户没有指定会话时, 默认只看当前会话; 只有用户指定了其他会话才读取它们的日志.

3. 在以下类别中寻找可改进的候选.

- **导航**: Agent 找到正确文件有多容易? 文件之间有没有隐藏的依赖? **导航指针** 能否让它更容易? _适用于_ 会话花了很长时间才找到某条信息.
- **自动检查**: 是否有自动检查能抓住 Agent 犯的错误? Lint, 类型检查, 测试, 文件系统 linter? 先读仓库自己的检查命令 (其 `package.json` 或构建工具的 `lint`/`check` 脚本, CI 工作流), 这样发现的是已存在却没接上或悄悄坏掉的检查, 而不是重新发明. 没有 **护栏** 的仓库 (既没有 pre-commit 钩子, 也没有运行其 lint/类型检查/测试命令的 CI 任务) 本身就是一个发现: 没有 lint 的仓库是一直存在的错失机会, 不是中性的默认状态. _适用于_ Agent 犯了自动检查本可抓住的错误, 或仓库完全没有护栏.
- **编码规范**: 独立 Reviewer 是否该新增一条要强制的规则? 已有规则是否该删除或澄清? 先对违规分类: **机械性** 的 (固定的语法模式, 被禁的 API, import 形态, 文件位置规则) 一律用确定性检查, 即仓库自己 linter 的自定义规则, 新的 pre-commit 钩子, 或新的 CI 任务, 取决于仓库语言和现有护栏下哪种最便宜. 默认构建检查而不是写规则. 只有真正的 **判断类** 规则 (跨文件一致性, "与周围风格一致", 任何护栏都无法替代的内容) 才写入 Code Standards Reviewer 会逐项应用的适用 Agent 指令 (通常是 `docs/agents/**` 中负责该主题的文档). _适用于_ Reviewer 没能抓住某个错误.
- **全局 AGENTS.md**: 有没有指导性指令应当移到编码规范 (或自动检查) 中? _适用于_ `AGENTS.md` 特别大, 无论在仓库范围还是用户全局范围.
- **工具经济性**: Agent 是否发起了昂贵的工具调用, 可以精简? 有没有特别耗 token 的自定义工具 (CLI, MCP)? _适用于_ Agent 发起了昂贵的工具调用.
- **无效指令**: 找出指导文件中不改变 Agent 行为的指令. _适用于_ 指导文件庞大难以驾驭.
- **信息获取**: 找机会提升 Agent 获取信息的能力, 如分流开发服务器日志, 对第三方服务的只读访问. _适用于_ 某条关键信息 Agent 没能获得.

4. 把这些候选按严重度从高到低呈现给用户. 每个候选写出目标路径和拟议改动要点.

5. 用户选定候选后再实施. 修改 Agent 指令, Skill, 规范或 ADR 等受保护文档时按 `$rule-and-design-changes` 执行: 用户选定带拟议文字的候选即视为对该文字的确认, 实际改动偏离时重新确认.

## Reference

### Implementation vs Review

所有工作都经过两个阶段: 实施和审核. 实施 Agent 的 **上下文压力** 最大, 它负责探索, 写代码和调试失败.

审核 Agent 的上下文压力最小: 它拿到的是 diff, 不需要探索, 通常也不需要写代码或调试.

所以应由审核 Agent 负责施行编码规范, 而不是实施 Agent.

### Files

你可以访问仓库中的几类文件:

- `CLAUDE.md`/`AGENTS.md`: 这些文件会被推入在本仓库工作的任何 Agent 的上下文窗口. 要极其节制地使用, 通常只放指向其他文件的 **导航指针**.
- `docs/agents/**`: 实施 Agent 按触发条件按需读取, Code Standards Reviewer 审核时读取并逐项应用全部适用指令. 判断类编码规范放在这里负责该主题的文档中, 不放进根 `AGENTS.md`. 某份文档超过 1000 行时, 添加指向其他文档的 **导航指针**.
- 文档: 把文档用作被其他文件指向的参考文件. 写新文档前先找已有文档.
- Skill: Skill 用于文档 (因为它的 description 会进入 Agent 的上下文窗口), 或用于用户调用的命令. 遵循 `$writing-for-agents` Skill 中的建议.
