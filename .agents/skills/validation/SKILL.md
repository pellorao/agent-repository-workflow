# 验证

根据活动 issue 和仓库声明的验证命令确定验证内容; 仓库在根 `AGENTS.md` 的 Repository-owned 区域声明运行器, 构建, 浏览器和在线验证命令. 不从来源项目推断这些命令, 也不添加仓库未选择的工具. 实施期间使用最小定向检查, 完成前取得完整仓库测试套件的有效结果.

## Required checks

报告任何实施或文档 issue 完成前, 取得以下检查的当前有效结果. 它们补充而不替代仓库测试套件:

- `arw text check` 通过.
- `arw terms check --include .scratch/<NNNN>-<effort-slug>/` 通过, 占位符替换为当前 issue 实际的仓库相对 effort 目录.
- Repository Profile 配置了 Code Map 时, `arw code-map verify` 通过. 它只证明结构覆盖; issue 改变了相应代码或目录责任时, 检查描述本身.

`arw terms check` 的语言结果不改变退出码, 退出码 `0` 不代替结果处理. 每次调用都消费 `arw.config.json` 中已配置的语言检查结果 (需要全部文档时加 `--verbose`), 不自行推断语言或阈值. `arw.config.json` 没有配置 `languageChecks` 时不做语言检查, 不询问用户. 未达阈值的文档需要修正或取得用户批准; 已配置但未覆盖, 没有选中文档或无法判断都不算通过, 向用户报告并取得处理决定; 配置错误修复后重跑. 用户批准只在当前 session 内覆盖其所述的文件范围和比例条件, 不写入仓库.

为每条验收标准记录具体证据, 指明支持结果的测试, 命令, 文件或检查. 通过的命令不能证明它没有实际检验的要求.

## Coverage

- 采用最少充分覆盖: 根据要求, 测试边界和实际回归风险选择能证明行为的最小测试集合. 参数差异只有在产生不同的可观察结果, 失败影响或恢复结果时才单独覆盖. 新增测试前确认现有测试不能证明该独立风险; 多个测试证明同一行为时, 保留成本较低且失败原因清晰的测试.
- 不写只重复实现逻辑的同义反复测试, 例如只断言文档包含某句规则; 验证供机器读取的固定格式除外.
- 常规测试不使用网络. 可行时把文件系统, 进程和在线服务行为隔离在仓库现有公开边界后面.
- 在已授权范围内自主选择普通和真实端到端案例. 日常工作已执行的真实端到端流程通常不新增测试; 日常几乎不覆盖且有独立回归风险的情境, 用具体可观察结果说明必要性并保留最少案例. 新增测试不授予改变产品语义, 扩大 issue 或删除核心覆盖的权限.
- 设计经过多个实现层产生可观察结果时, 直接验证最终结果. 只有中间值本身属于公开合同, 持久证据, 授权或安全边界, 或最终结果无法证明受治理的属性时, 才单独要求该中间值.
- 按 `docs/agents/writing.md` 的 Batch operations 应批量处理的操作, 比较不同输入规模, 验证全部输入和必要语义得到保留, 且可合并的调用次数不随数据项增加; 批量写入还要验证授权范围, 失败影响, 重试, 恢复和事务结果. 独立事实需要独立操作时, 不断言固定调用总数, 也不把实际耗时作为自动失败条件.
- 创建或语义修改测试案例, 或以降低套件耗时为目标时, 使用 `test-performance-optimization` Skill. 用户主动要求清理低价值测试时, 使用 `test-value-cleanup` Skill.

## Reuse and parallel runs

互不依赖且没有共享写入冲突的检查可以并行. 运行前明确每项检查的候选版本, 配置, 依赖, 环境和验证合同; 这些输入准确相同且没有新失败或反证时, 复用已完成的有效结果, 真正变化时按实际影响重跑. 复用不缩小必要覆盖, 不以定向检查替代完整套件, 不把未完成检查或相似输出当作通过. 必须在特定授权时点取得的结果, 保留该时点的核对.

耗时检查可以在按 `docs/agents/environment.md` 准备的普通候选快照中运行, 但先证明全部必要来源和执行环境等价. 依赖实时索引, 当前就绪设计或 Git 可见文档的最终检查在主仓库对准确版本执行. 主工作树的其他修改不能混入快照或被当作快照结果的证据.

## Documentation changes

对已更改的投射工作流文档, 检查路径, 标题, 精确命令, 跟踪器字段, 内部链接, 没有 BOM 的 UTF-8 和 LF 行尾, 以及 `docs/agents/writing.md` 规定的文档语言. 对 Agent 负责的已跟踪内容用明确的路径列表运行 `git diff --check`, 单独检查未跟踪内容. 纯文档工作记录这些检查, 不编造无法检验该变更的行为测试.
